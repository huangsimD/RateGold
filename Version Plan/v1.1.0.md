## 4. 功能描述

### 4.1 Ops — 分析看板（#1）

- **目标**：运营一眼看到测试/埋点用户规模与活跃健康度。  
- **行为**：管理页展示总用户、今日新增、今日 `screen_view`、DAU/WAU、D1/D7、近 7 日表。  
- **验收**：有事件上报后指标非零且与事件日一致。  
- **依赖**：事件 API、Admin Basic Auth。

### 4.2 Ops — 用户列表（#2）

- **目标**：按匿名设备查看使用情况，不做实名账号。  
- **行为**：列表字段含 install_id、首末活跃、打开次数、最近屏幕、app_version、locale；支持分页与关键字搜索。  
- **验收**：新 install_id 出现在列表；搜索可用。

### 4.3 Ops — 事件接收 API（#3）

- **目标**：接收 App 匿名事件并落库。  
- **行为**：`POST /v1/events` 支持单条或批量（≤50）；校验 `X-Ops-Token`；生产写 GitHub 私有 Gist。  
- **事件类型**：`first_open` / `app_open` / `screen_view`。  
- **验收**：Health OK；上报后 dashboard/users 可见。

### 4.4 Ops — 正式服部署（#4）

- **目标**：公网可访问的运营后台。  
- **行为**：Vercel 托管 `ops/`；README / 仓库 homepage 公示链接。  
- **验收**：https://rategold-ops.vercel.app/health 返回 ok。

### 4.5 Ops — Play 商店页（#5）

- **目标**：在不更新现网 App 包的前提下查看 Play 侧安装/活跃。  
- **行为**：侧栏「Play 商店」；手动粘贴 CSV 保存快照；可选配置 Reporting API 后一键刷新。  
- **验收**：保存 CSV 后卡片与表格有数据；未配 API 时页面提示清晰。  
- **说明**：现网 `1.0.0+2` **不会**自动上报到 Ops 埋点看板。

### 4.6 App — 可开关匿名埋点（#6）

- **目标**：测试包可观测，正式包默认可关闭以免违规。  
- **行为**：`String.fromEnvironment('OPS_BASE_URL')` 为空则全部 no-op；持久化 UUID 为 install_id。  
- **验收**：无 define 的 release 抓包无 Ops 请求；有 define 的测试包有请求。

### 4.7 App — 冷启动 / 屏幕事件（#7）

- **目标**：支撑看板 DAU 与浏览统计。  
- **行为**：首次 `first_open` + 每次冷启动 `app_open`；路由变化 `screen_view`（board/convert/settings/gold 等）。  
- **验收**：切换 Tab 后 Ops 出现对应 screen。

### 4.8 构建 — Closed testing / 正式包（#8–#9）

- **目标**：测试与生产构建隔离。  
- **行为**：`build_ops_test_aab.ps1` 打 `1.1.0+3` 并注入 Ops URL；`build_release_aab.ps1` 不注入。  
- **验收**：两脚本产物 versionCode / 埋点行为符合预期。

### 4.9 合规 — Production 埋点门槛（#10）

- **目标**：含埋点包进 Production 前合规。  
- **行为**：更新 Data Safety、隐私政策与内部 data-safety 文档后再放量。  
- **验收**：Play 声明与实际采集一致。

### 4.10 产品暂缓项（#13–#14）

- **多语言**：已在 V1，本版不迭代。  
- **Pro**：见 PRD「V1 免费 → V1.1 订阅」——目标价提醒、Widget、Billing；**等运营与留存信号后再开独立 Version Plan 条目或新版本文件**。
